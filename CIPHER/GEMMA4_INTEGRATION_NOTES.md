# CIPHER + Gemma 4 integration notes

This package is based on the supplied existing CIPHER project (`CIPHER_CLEAN_FINAL`). It preserves the existing app, authentication, evidence pipeline, graph/Neo4j modules, frontend, and database code. It does not replace CIPHER with a separate starter application.

## What changed
- Set the default `GEMINI_MODEL` used by the existing Google Generative Language API calls to `gemma-4-26b-a4b-it`.
- Updated environment examples and deployment defaults to show Gemma 4.
- Kept the existing LLM provider/fallback architecture and existing API routes.
- Added this integration note.

CIPHER already had Google Gemini API-call plumbing. Gemma is selected through that same Google Generative Language API model parameter, so this integration reuses the existing code path rather than adding a second standalone app.

## Before running
1. Check that the model ID is available to your Google AI Studio/API account and is permitted by the event rules. Model availability and identifiers can change.
2. In your real root `.env` file, set:
   ```env
   GEMINI_API_KEY=your_private_google_ai_studio_key
   GEMINI_MODEL=gemma-4-26b-a4b-it
   ```
3. For the provider chain, the project currently supports `LLM_PROVIDER=auto` and a fallback order. To prioritize the configured Google model, keep `gemini` first in `LLM_FALLBACK_ORDER`.
4. Restart the backend after changing `.env`.

## Run (Windows)
From the project root, follow the existing README/deployment instructions. The usual local command is:

```powershell
python -m uvicorn python_backend.main:app --reload --port 8000
```

If your existing start script uses a different command, keep using that project-specific command.

## Test
- Open `http://127.0.0.1:8000/docs` and use the existing authenticated CIPHER AI query endpoint.
- Check `/api/config` for the configured provider status (the endpoint reports whether a Google API key is configured, not whether the model call succeeded).
- Test one synthetic case note and inspect backend logs for model/API errors.
- Test login, case CRUD, evidence processing, and graph endpoints after the change.

## Important
- Do not commit `.env` or API keys.
- Use synthetic or approved data for the demo.
- AI output is an investigative lead, not proof. Human investigators must verify all outputs against original evidence.
- The default model string is a configuration choice, not a guarantee of access. If the API reports that the model is unavailable, select a Gemma model ID that is actually offered to your account. Do not claim a Gemma-powered run unless the output was genuinely generated by Gemma.
